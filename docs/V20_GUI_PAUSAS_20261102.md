## Corrección del ensayo de ventana larga

El helper antes siempre seleccionabaFFT. Pedir una ventana temporal no bastaba para ejercitar el dibujoV(t): la primera corrida completó audio pero falló correctamente la exigencia de raster temporal. Una segunda configuración usando `--analysis-mode vt` publicó raster y completó audio, pero arrastró criterios de análisis sin generador (`a0_remained_off` y curvas tradicionales) que no corresponden a RADIO/A0 ni a una imagen raster.

Se separó la visualización `--radio-time-view` de los escenarios de análisis puro. `--window-seconds` selecciona ahora V(t) con criterios RADIO/A0; no se desactivan ni ocultan comprobaciones de audio. Los modos incompatibles se rechazan antes de crear la ventana.16tests focalizados PASS; este cambio es sólo de herramientas. Las dos corridas anteriores y sus errores de comprobación se conservan.

La prueba revela una limitación de velocidad de dibujo, no un bloqueo equivalente del hiloGUI:

- El worker de raster informó tiempos de3.294/3.069/3.115/3.006ms duranteRADIO. Sólo se observaron7imágenes publicadas en las muestras periódicas de todo el ciclo. No se convierte eso en un FPS visible preciso.
- El callback de render principal llegó a156ms y el contador de separación de heartbeat registró737ms (incluye inicio). El archivo de pilas quedó vacío; no prueba que nunca existiera un hueco≥700ms fuera del intervalo armado.

El siguiente candidato es reducir el coste del raster de millones de muestras manteniendo comparación de píxeles, continuidad y huecos sin datos. No se incorporó ningún algoritmo nuevo de raster ni paralelismo extra en este bloque. El coste de3s por imagen no debe atribuirse a la frecuencia de actualización del ADC ni considerarse un pase de FPS.
